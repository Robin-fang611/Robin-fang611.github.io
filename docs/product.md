# 产品命题：Robin 的个人主页（卷宗版）

> 版本 2026.10 · 取代 `Robin-fang611.github.io` 的「宣纸墨章」单页版
> 仓库：`Robin-fang611/Robin-fang611.github.io` · 分支 `revamp/frontend-logic`

---

## 0. 一句话命题

**给一个在 60 秒内要判断「这个人能不能把我的 AI 项目推进到真实业务里」的合作方、招聘方与同路人：把主页做成一份可以逐条核对的卷宗——先给结论，再给证据，最后给下一步。**

不是「介绍我」，是「替访客完成一次判断」。所有版式、层级、动效都为这次判断服务；判断完了，页面就该结束。

---

## 1. 苏格拉底式盘问

写代码之前先把问题问穿。下面每一问都对应一个已经被砍掉或重做的设计决定。

### Q1：这个页面存在的唯一理由是什么？

常识答案：让访客了解我。
反问：访客不缺「了解」，缺的是**判断依据**。一个人对陌生人的好奇最多维持两屏；两屏之内给不出可核对的东西，后面写得再好也不会被读。

结论：主页的职能是**递材料**，不是写自传。页面结构 = 一次尽调的阅读顺序。

### Q2：谁会来，各停留多久？

| 读者 | 时间预算 | 他要完成的判断 | 需要什么 |
|---|---|---|---|
| 合作方 / 客户（传统企业、AI 公司） | 2–3 分钟 | 他懂不懂我的业务？交付过没有？ | 同类案例、结果、能否约谈 |
| 招聘方 / 猎头 | 30–60 秒 | 他的定位与可迁移成果是什么？ | 一句话定位、两三个结果、联系方式 |
| 同路人 / 开发者 / 社群 | 1–3 分钟 | 值不值得认识？ | 社群、开源作品、正在想什么 |

结论：首屏必须同时回答「是谁 / 做过什么 / 怎么联系」；三类读者共享一条主路径，在结尾分叉。

### Q3：现有页面替谁完成了判断？

- 开头 **470vh** 的钉住 + 帘幕：前两屏没有任何可判断信息，只有氛围。访客在被证明之前先被要求耐心。
- **9 个数字**并列：单位混杂（人 / 个 / 万+ / % / 所），没有出处，读者无法比较，也无法相信。
- **8 段经历 + 5 条方法 + 5 条思考**平铺：没有主次，读者得自己总结。
- 中英两个 **40KB 文件**：同一事实写两遍，改一次漏一次——这次核对时，README 与站点已经互相矛盾（客户、头衔、社群规模全对不上）。

结论：旧前端在视觉上成立，在**逻辑**上不成立——它按作者的经历顺序排版，而不是按读者的决策顺序。

### Q4：如果只能留三块？

1. 一句定位：他是谁、服务谁。
2. 三个可核对的结果：客户项目、社群、游戏——每个带数字与出处。
3. 一个明确的下一步：合作 / 工作 / 社群，带联系方式。

其余内容不删，**下沉**：想深看的人能翻到，不想的人不必经过。这就是三档深度（见 §3）。

### Q5：方法和思考放哪？

它们是差异化，但属于「决定要不要认识你」**之后**的材料。放在履历之后，标题写成「我怎么工作」「我正在想什么」，每条不超过三行。观点要能被反驳，不写正确的废话。

### Q6：为什么视觉是「卷宗」而不是又一次水墨风？

因为 Robin 的真实工作方法是驻场、访谈、核对基线——他的可信度来自**材料感**。卷宗（编号、章节、出处、页边注、朱印）不是装饰，是把「可核对」变成可感知的形式。

- 底色：宣纸（承接旧版，保留品牌连续性）
- 唯一强调色：朱砂（印章、数字、当前章节）
- 字体：宋体承担标题与数字（材料、权威），黑体承担正文（可读）
- 唯一「合理意外」：每章右上角的朱砂编号印，像盖章的尽调材料

### Q7：为什么前端会变成两份 40KB HTML？

因为内容、结构、样式、动效全塞在一个文件里，**没有数据层**。改一句文案要改两处；加一个章节要手抄整段 HTML；换一次视觉就要重写整页。

这次重构的判据不是「代码更漂亮」，而是三条可验证的工程事实：

1. 改一条事实，只改一个地方（`src/content/site.mjs`）；
2. 加一个章节，只写一个渲染函数并登记进目录；
3. 关掉 JavaScript，内容仍然完整可读（渐进增强）。

### Q8：动效留多少？

旧版每帧重写 body 背景、18 个面板 transform、7 个鼠标拖尾点，即使页面静止也在跑。动效压过了内容，而且**内容可见性依赖 JS**（`.rv` 初始 opacity:0）。

结论：动效只保留三处——首屏标题一次墨线书写、悬停/焦点的微位移、章节印章的轻微旋转。不加滚动入场、不加数字滚动、不加平滑滚动劫持。**内容默认可见**，JS 只做导航与工具。

## 2. 受众与路径

一条主路径，结尾分三叉：

```
首屏（10 秒）→ 三份证据（2 分钟）→ 履历 / 生态（5 分钟）→ 方法 / 议题（10 分钟）→ 联系（30 秒）
                                                                     ├─ 合作：驻场做 AI 落地
                                                                     ├─ 工作：增长 / 产品角色
                                                                     └─ 社群：活动、黑客松、内容
```

导航（章节目录）常驻左侧，当前章节用朱砂标记；移动端收进「目录」按钮（原生 `<dialog>`）。

## 3. 信息架构：三档深度

| 档 | 区块 | 回答的问题 | 形态 |
|---|---|---|---|
| 一档 · 判断 | 封面 | 他是谁？ | 一句定位 + 三个身份 + 两个动作 |
| 一档 · 判断 | 01 摘要 | 他解决过什么？ | 三行案例：问题 → 做法 → 结果 + 出处 |
| 二档 · 核对 | 02 证据 | 数字可信吗？ | 6 条数字，每条带口径与时间 |
| 二档 · 核对 | 03 履历 | 一直在做吗？ | 四章时间线，早期折叠 |
| 二档 · 核对 | 04 生态 | 和谁一起？ | 4 个角色 + 合作伙伴 |
| 三档 · 深看 | 05 方法 | 怎么工作？ | 4 条，可反驳 |
| 三档 · 深看 | 06 议题 | 在想什么？ | 3 条判断，带依据 |
| 行动 | 07 联系 | 下一步？ | 三类诉求 + 邮箱 / 微信 / 社交 |

编号即目录，编号即锚点。读者随时知道自己在第几章。

## 4. 内容规则

1. **数字必须有口径与时间**：写成「1,700+ 人 · 零投流 · 2026.10」，不写孤零零的「1600+」。
2. **客户脱敏**：公开页面不写客户全名，写「华南某国际货代（已脱敏）」；合作方私聊再给全名。
3. **不写正确的废话**：删掉「赋能 / 一站式 / 闭环生态」这类词；每条方法要能被反驳。
4. **区分事实与判断**：「已上线」「好评率 100%（样本有限）」是事实；「模型会商品化」是判断，标在议题章。
5. **不虚构**：只在简历、GitHub、公开材料里出现过的数字才上页面；拿不准的加限定词或删掉。
6. **中英同源**：两种语言共用一份数据，英文是翻译不是另写；不允许出现两套事实。

---

## 5. 与 GitHub Profile 的关系

- **站点** = 完整卷宗（可读、可核对、可打印）。
- **Profile README** = 卷宗封面的一页摘要：定位、三份证据（带链接）、在做什么、怎么找。它必须和站点**共用一套事实**，不再单独维护第二套叙事。
- 两边更新顺序：先改 `site.mjs` → 生成站点 → 同步 README 摘要段。

---

## 6. 不做什么

- 不做作品集瀑布流、不做暗色/亮色切换（卷宗只有一种纸）。
- 不做滚动劫持、不做鼠标跟随、不做数字滚动动画。
- 不做中英两个独立页面文件（同一渲染器，两个 locale）。
- 不引入前端框架、不引入 CDN 字体（国内访问不可靠）、不加任何第三方脚本。
- 不放客户 logo 墙（未经授权），不放 GitHub Stats 卡片（数字不好看且与叙事无关）。

---

## 7. 验收口径

- 首屏在 1440×900 与 390×844 下都能看到：定位、三个身份、主 CTA。
- 三档深度可在 10 秒 / 2 分钟 / 10 分钟三个节奏下读完，不需要回滚找信息。
- 每条数字都能在页面上找到出处与时间。
- 关闭 JS：全部内容可见，锚点与折叠可用。
- 评审器：0 Critical / 0 High；对比度全部 ≥4.5:1（大字 ≥3:1）。
- 构建：`npm run build` 一条命令产出站点，无外部依赖。
