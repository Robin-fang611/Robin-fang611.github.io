# GitHub Profile 的苏格拉底式整理

> 为什么这份 README 长这样。对应分支 `revamp/2026-10-dossier`。

## Q1 一个陌生人打开 GitHub 主页，他实际在做什么？

不是读简历，是在决定**要不要点进某个仓库、要不要发一封邮件**。主页是入口，不是容器。README 的任务是把这个决定推进到下一步，而不是把所有经历倒出来。

## Q2 旧 README 的第一屏在做什么？

打字 SVG、徽章、About Me、三个项目。它在「表演一个开发者主页」，但没有回答两个最基本的问题：**他现在在做什么？最近做成了什么？**

而且：打字 SVG 是第三方请求（国内经常加载不出来）；内容停在 7 月；「首位客户深圳华邦通运」「独立 FDE 开发者」「武汉美食地图 540 家」与站点、简历的口径互相矛盾。

## Q3 为什么删掉 typing SVG 和徽章？

它们不携带可核对的信息，还要额外请求第三方。GitHub 原生 Markdown 最快、最稳，也最像「材料」。徽章墙证明的是技术栈，而他的差异不在技术栈，在「能不能把 AI 带进真实业务」。

## Q4 那份 README 应该由什么构成？

1. 一句定位：谁、服务谁。
2. **现在**：三个角色，一行一个。
3. **三份证据**：结果 + 出处 + 链接。
4. **公开仓库**：可点、可验证。
5. **我在找什么**：合作 / 工作 / 社群三条路径 + 联系方式。
6. 英文摘要：折叠，给非中文读者 20 秒。

## Q5 为什么是「三份证据」而不是「精选项目」？

「项目」是作者视角，「证据」是读者视角。每条证据必须回答：问题是什么、做了什么、结果是多少、谁在用。三个比五个好记，而且刚好覆盖三种能力：客户交付、社群运营、游戏制作。

## Q6 为什么 Linkathon 写「早期共建者」而不是「发起人」？

公开表述宁可保守。社群协议对角色称谓有约束，未经发起团队确认的头衔不写。同理：客户名脱敏、玩家数不写、「100% 好评」必须带「10 篇评测，样本有限」、美食地图的 832 家标「2026.08 快照」。

## Q7 为什么保留英文摘要？

GitHub 是国际入口。英文摘要让非中文读者在 20 秒内知道你是谁，同时不必维护第二套完整叙事——它不是翻译整页，而是同一份事实的压缩。

## Q8 为什么 README 必须和站点共用一份事实？

旧版最大的问题不是设计，是**两套事实**。一处更新、另一处不动，读者一旦发现矛盾，前面所有数字都不可信。

规则：先改站点 `src/content/site.mjs`，再同步 README；每个数字带口径与时间；没有出处的数字不上页面。

## 结果

README 从「一个开发者主页的模板」变成「一页尽调摘要」：定位 → 现在 → 三份证据 → 公开仓库 → 三条路径 → 联系。没有徽章、没有统计卡片、没有第三方图片。

站点是完整卷宗，README 是封面那一页。
